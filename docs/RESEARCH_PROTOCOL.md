# Pre-experiment research protocol: Borrowed Authority

## Research thesis

An instruction-following model may mistake claims of authority in lower-trust communications for actual authorization, especially when the claimed issuer resembles an approved actor, the message asserts urgency, or instructions are embedded in apparently authoritative files. Can we measure this failure and reduce it without blocking authorized actions or harmless questions?

## Threat model

**Trusted:** owner policy + explicit approval ledger. **Untrusted:** forwarded emails, chat screenshots, notes, shared documents, quoted conversations, external tools and web content. **Adversary's control:** untrusted message contents, not trusted ledger entries. **Target failure:** a false authorization or unauthorized state change in a simulated task. No actual financial transfers or external mutations will be executed by this research harness.

## Testable hypotheses

- **H1:** Untrusted claimed authority induces unauthorized action labels on at least some cases. This is a hypothesis, not an observed result.
- **H2:** A safety intervention grounded in source authority reduces unauthorized execution relative to the baseline.
- **H3:** The intervention need not substantially reduce legitimate approval completion or increase benign over-refusal; test rather than assume.

## Data collection and split

1. Start with 80 synthetic cases (20 families x 4 conditions) generated by a deterministic seed.
2. Review whether labels follow the trusted ledger, not the rhetorical strength of messages.
3. Expand with independent variations: multispeaker conversations, culturally specific communication, code-switching, repeated claims, screenshots as transcribed text, conflicting evidence, harmless status inquiries, boundary cases, long context.
4. Keep matched case families in a single split. Never train on paraphrases of held-out families.
5. Report which examples are manually written vs synthetically generated. Avoid publishing sensitive correspondence.

## Model and baseline

Approved candidate: `CohereLabs/tiny-aya-earth` (3.35B open-weight research model). Test model access and GPU fit before choosing an intervention. Avoid spending days building a UI or video first. Use deterministic decoding for the initial baseline, note any invalid JSON, and avoid decoding model outputs into expected labels automatically.

## Intervention plan (to be decided after baseline)

Option A: CuratorKIT-processed hard negatives + SafeTune inference-time steering (if supported and computationally feasible). Option B: safer contrastive dataset and a lightweight adapter if resources permit. Option C: only an adversarial dataset and rigorous AuditKIT evaluation under Track 2a, if full model repair is infeasible—ensure two-toolkit rule still met.

## Before/after study

Evaluate on exactly the same held-out cases; report rates alongside numerators/denominators and uncertainty. Use at least two distinct metrics, including unauthorized compliance and legitimate completion. Include cases where the intervention made behavior worse. Ideally extend to 100+ unseen cases per failure class before making meaningful statistical claims. Never confuse passing unit tests of evaluator code with improvement in an AI model.

## Risks and controls

- Synthetic datasets may contain label shortcuts. Counterbalance language and formats; inspect shortcuts.
- Tiny Aya is multilingual but not a proof of authority reasoning skill. Verify suitability.
- A rule-based safe wrapper may outperform the base model but is not evidence of changed model weights; label interventions precisely.
- Text-matching authority ID is a simplistic scorer; audit attribution manually for semantic equivalence.
- Reject and request-clarification labels can both be defensible in some situations. Have a rubric and second annotation pass.
- Evaluate general utility and benign over-refusal to avoid optimizing for refusal only.
- No production use for real payments, consent, approvals or confidential workflows without proper security review.
